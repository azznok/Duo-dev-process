# Asset pipeline (3D models, sounds, textures) — PROPOSAL, to be validated by the owner

> WRITTEN BY: the template (proposal), completed by the duo (lessons paid for). BUDGET: 220 lines.
> **Nothing here applies until the owner validates it** (`docs/QUESTIONS.md`). Until then: NO binary
> asset enters the repo; everything is generated by code or comes from a free pack listed in
> `docs/CREDITS.md` (`docs/RULES.md` § Production). Once validated: an ADR records it, this file
> leaves `docs/parking/`, and the amendment of § 12 goes into `docs/PROJECT-RULES.md` (owner only).
> Step by step and traps: skills `pipeline-3d` and `pipeline-audio`.

## 1. Why, and for what only

Code generates boxes, panels, terrain, procedural shapes and colours very well. It generates
**sounds** badly, and maybe a few **organic or detailed objects** (a creature, a hand-held tool, a
character). This pipeline exists for them only. The style stays the one of `docs/ART-DIRECTION.md`:
an asset that breaks it is refused, however good it is alone. **Flat-faced objects** (boxes,
chamfers, frames, panels, pipes) are cheaper, exact and cleaner **built by code** (`tools/mesh/gltf_lib.py`,
or a Blender script): 0 credits, dimensions exact, iterate on numbers instead of on a mesh.

## 2. Tools and roles

| Tool | Role | What it does NOT do |
|---|---|---|
| Meshy (`tools/gen/meshy.py`, MCP `meshy`) | concept images (image-to-image from a reference), image -> 3D, texture, humanoid rig | rig a non-biped; clean hard-surface |
| Blender (MCP `blender`, headless `blender -b --python`, `tools/blender/`) | scale, pivot, orientation, cleanup, decimation, bake, collision, non-humanoid rig, short animations | judge for you |
| `tools/mesh/` | primitive kit at exact size (0 credits), measurement, matte materials | — |
| ElevenLabs (`tools/gen/elevenlabs.py`) | sound effects from a text prompt | music, voices without a licence decision |
| `tools/audio/` | gate, measured conversion (WAV / OGG), listening page | listen (the owner listens) |
| The app itself | the capture that judges (skill `proofs`) | — |

Order: **search -> image -> validate -> 3D -> clean -> measure -> in the app -> the capture judges.**

## 3. Search BEFORE generating (mandatory)

1. What the project already has: reuse, recombine, recolour.
2. Free sources (CC0 first, CC-BY with credit): 6 sources and 20 minutes at most, then decide.
   Criteria: licence, triangle budget, style compatible after recolour, importable format.
   The licence goes into `docs/CREDITS.md` AND into the asset's recipe (§ 6).
3. Stores without an API (account, terms to accept, purchase): never by an agent. A need sheet
   in `docs/parking/`; the human buys and drops the file into `assets_src/purchased/`.
4. Generate: only if 1 to 3 gave nothing, for an asset the PLAN or the task names.

## 4. Iterate on the image, not on the 3D

| Step | Attempts at most | Note |
|---|---|---|
| Concept image (image-to-image from the validated reference in `docs/art/refs/`) | 6 | cheap, legitimate iteration |
| Raw 3D (no texture) | 3 | beyond that, the problem is in the image |
| Texture | 1 | only after the silhouette is validated |
| Auto rig | 1 | humanoid biped only; otherwise Blender |

- **Budget per asset: 150 credits** (adjust in the PLAN). Over it: stop, write it in `docs/STATE.md`, next asset.
- Image-to-image needs a reference (the reference carries the style) and takes 5 at most.
- 3D from **flat** views only (front, side, back), never a three-quarter view (the model comes out
  squashed). Creatures and characters: never free text -> 3D.
- Fix the polycount explicitly; some models ignore it: the budget is held at cleanup.

## 5. Formats and places

| Type | Shipped format | Sources (LFS) | Rule |
|---|---|---|---|
| 3D model | **GLB** (glTF 2.0 binary): meters, Y up | `assets_src/3d/<name>/` (concept png, raw GLB, cleanup script output) | budget § 8, <= 3 materials |
| Sound | **OGG Vorbis** (or WAV if the stack wants it), 44.1 kHz, mono (stereo: ambience, music), peak -1 dBFS | `assets_src/audio/<name>/` (raw mp3, variants) | gate passed; `tools/audio/convert.py` |
| Texture (only if really needed) | **PNG**, <= 1024 px | `assets_src/tex/<name>/` | no photo texture unless the art direction asks |

The shipped folder (`assets/` or the engine's content folder) is set at onboarding (skill `stack`).
An engine that is not glTF-native (Z up, centimetres) converts on import: write the conversion once
in the skill, and measure the result in the engine, not in the GLB.

## 6. One text recipe per binary

A binary does not exist without its recipe, versioned, readable by an agent, next to it or in
`assets/recipes/<type>/<name>.<json|ron|toml>` (the project's data format):

```
id: "door_open"            kind: sound
output: "assets/audio/sfx/door_open.ogg"
origin: generated(tool: "elevenlabs", prompt: "...", params: {seconds: 2}, variant: "b")
        | free(url: "...", licence: "CC0-1.0") | code(tool: "tools/mesh/...py", args: "...")
sources: ["assets_src/audio/door_open/raw_b.mp3"]
steps: ["python tools/audio/gate.py ...", "python tools/audio/convert.py ... --mode hit"]
budget: none | tris(1500)     credits: 200     validated: "<date>, owner"
```

- The app never names a binary in code: it is **referenced by data** (the project's data files),
  and a check (test or data validator) proves: every referenced file exists, every shipped binary
  has a recipe, every recipe points to an existing file.
- A source over 10 MB stays on the owner's disk: the recipe names it with its size ("NOT in git").

## 7. Git: LFS before the first binary

- Declare the types in `.gitattributes` BEFORE the first commit of one (a binary enters history forever):
  `assets_src/** filter=lfs diff=lfs merge=lfs -text` and `*.glb`, `*.ogg`, `*.wav`, `*.mp3`, `*.png`
  under the shipped folder. After `git add`: `git lfs ls-files` lists them.
- Nothing over 10 MB in a commit (`docs/RULES.md` § Git). Discarded versions stay out of git.

## 9. Gates — numbers, never "is it pretty?"

- **A — concept sheet**: the views show the same thing (proportions, colours); silhouette readable
  black on white; style block of `docs/ART-DIRECTION.md` word for word; plain background.
- **B — raw mesh**: <= triangle budget (`tools/mesh/glb_measure.py --budget N`); nothing VISUALLY
  detached (a generated mesh is made of overlapping shells: judge on the image, not on a counter);
  bounding box +-10 % of the target (`--nodes` for the true box per node).
- **C — production ready**: scale and unit of the engine; pivot on the ground, centred; facing the
  agreed axis; conforming name; UVs without overlap; simple collision present.
- **D — in the app**: capture at the distances the player sees it (near and far), readable at both,
  palette conforming; next to the validated concept (`tools/image/sheet.ps1`); server AND client if replicated.
- **E — animation**: contact sheet of 6 frames over the loop (`tools/blender/contact_sheet.py`);
  box stable (+-50 %); loop without a jerk.

A failed gate = back to the previous step, not a new generation.

## 10. Asynchronous — NEVER wait in a loop

- Launch, go work, come back to harvest at natural boundaries (end of step, before a build).
  **2 Meshy jobs in parallel at most.**
- The in-flight file is written BEFORE waiting (`.state/gen_in_flight.json`): a paid job survives
  a dead process; `python tools/gen/meshy.py resume` harvests it.
- Every download lands in `assets_src/<type>/<name>/` with its prompt BEFORE any import: an engine's
  imported file is never the only copy.
- A generated asset replaces an existing one only if it passes ALL the gates.

## 11. Sound: direction and production

**Direction (to fill with the owner):** the intent in one sentence; the layers from the most
frequent to the rarest (1. the player: steps, breath; 2. the structure; 3. the event; 4. the alert);
what is OUT (rejected sounds and why). **No continuous ambience by default**: a looping background
tires and masks the signals; it enters only by decision.

- **Agents never play a sound.** The proof of a sound: the shipped file (duration, loop flag re-read)
  and the log line that says it was triggered at the right moment. Never "I heard it".
- **The owner listens** on a listening page (`tools/audio/listen_page.py`), on headphones AND on
  speakers, and answers by number: keep / redo (how). A generated sound enters only after that yes.
- **Prompt**: never "quiet", "faint", "near-silent", "barely audible" (the generator returns hiss, hum or
  inaudible sub-bass; the tool refuses these words). Always AUDIBLE and precise: source, material,
  gesture, distance, count ("four slow heavy footsteps on a metal grating"). The tool adds the
  anti-hum suffix. Fixed duration; `--loop` only for a real loop.
- **Gate** (`tools/audio/gate.py`): content above 200 Hz louder than -40 dB; dominant line (+-3 Hz)
  under 15 % of the energy. REJECTED = never offered.
- **Source to app**: raw in `assets_src/audio/<name>/` (never modified) -> `tools/audio/convert.py`
  (`hit` trimmed and faded, `loop` measured seam, `split` attacks at the same level; high-pass 40 Hz)
  -> shipped folder -> referenced by data; relative level set in data (the file peaks at -1 dBFS).
- A replaced sound is deleted only after a grep proves nothing cites it.
