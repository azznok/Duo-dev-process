# Duo-dev-process

**A plug-and-dev template to build a game or an app with autonomous Claude agents.**

You describe what you want. A *supervisor* Claude session interviews you (vision, stack, art direction,
milestones), writes the project's rules and roadmap, then launches one or two **duos** of agents that work
on their own, day and night: a **reviewer** that plans and judges, a **coder** that builds and proves. You
answer their questions when they have some, and you play/use a build every few days.

It was extracted from two real projects (an Unreal game, then a custom-engine game built by two duos over
~650 tasks), and every rule in it answers a cost or an incident that was **measured** there — see
[docs/TOKEN-ECONOMY.md](docs/TOKEN-ECONOMY.md).

## What you get

- **A duo that does not need you**: one task at a time, tests first, proofs (screenshots next to a
  reference, scripted scenarios, raw input scripts), one branch per task merged only after review.
- **A reviewer that cannot be fooled by "it compiles"**: the harness runs the checks itself (the *gate*),
  hands the reviewer a prepared judgment packet, and a separate *blind judge* compares captures to their
  references without reading the coder's excuses.
- **Two duos in parallel** on disjoint *lanes* of the backlog, with an orchestrator that relaunches them and
  a *mediator* that solves blocked merges.
- **A supervisor** that talks to you in plain words, carries the agents' questions (each with a default if
  you stay silent), writes your decisions as ADRs, and watches the logs without spending tokens.
- **Token economy built in**: fresh session per task, model chosen per task, MCP servers per domain, free
  sleep when there is nothing to do, quota memory, bounded files, thumbnails instead of full images.
- **A process that grows**: thin domain skills that the agents complete when a procedure repeats or a trap
  is paid; generic lessons flow back to this template (`docs/UPSTREAM.md`).

## Quick start

1. **Make it your repo**: click *Use this template* on GitHub (or copy the folder and `git init`), then
   point `origin` to your own repository.
2. **Prerequisites** (Windows 10/11 for the harness; the product can target any platform): Git for Windows
   with Git Bash, git-lfs, Python 3.11+ (`python -m pip install -r requirements.txt`), the
   [Claude Code](https://claude.com/claude-code) CLI, logged in. `bin\doctor.bat` checks everything.
3. **Open the folder in Claude Code** (desktop app: new session in this folder; or `claude` in a terminal)
   and say hello. The session sees the project is not onboarded and becomes the **supervisor**: it runs
   [supervisor/ONBOARDING.md](supervisor/ONBOARDING.md) — about 20 questions, one at a time, in a question
   panel, with a recommended answer each time:
   - the product (pitch, platforms, audience, references, pillars, what it is NOT),
   - the stack (engine/framework, pinned version, test tools, **how agents will take screenshots and drive
     inputs**),
   - the art and UX direction (your reference images, a board, one direction chosen),
   - assets and paid services (code-generated by default; optional Blender/Meshy/ElevenLabs; phone
     notifications with ntfy),
   - scope and milestones (what "v1 is done" means; M0 foundations, M1 first slice, ...),
   - running costs (model table, one or two duos, build cadence).
4. It writes `docs/VISION.md`, `docs/PROJECT-RULES.md`, `CLAUDE.md`, `docs/ART-DIRECTION.md`,
   `docs/ROADMAP.md`, `docs/PLAN.md`, `config/project.env`, the `stack` skill and one ADR per decision, runs
   the doctor, and asks **"Start the duo now?"**
5. From then on: talk to the supervisor. It relays what the duos did, asks you their questions, and tells you
   when a build is ready to play/use. Stop everything with `bin\harness\stop.bat`.

## How it works

```
you ──> SUPERVISOR session ──writes──> pipeline/owner.md, docs/adr/, docs/PLAN.md
              ▲ watch.sh (no model)                 │ (read as a diff at the next pass)
              │                                     ▼
        ORCHESTRATOR ──> duo A: reviewer -> coder -> gate -> reviewer -> ...   (lane 1)
         (no model)  └─> duo B: same loop, own worktree and build folder        (lane 2)
              │ incident (blocked merge, fatal error)
              └──> MEDIATOR (model chosen by incident type)
```

- One task = one branch `task/<nnn>-<entry>`, merged into `main` by the harness only after
  `VERDICT: ACCEPT`.
- Nothing to do without you: the reviewer writes `TASK: NONE` and a question; the duo sleeps **without
  spending** until you answer.
- Details: [docs/HARNESS.md](docs/HARNESS.md) (the machine), [docs/WORKFLOW.md](docs/WORKFLOW.md) (roles,
  task format, definition of done, reviewer checklist), [docs/RULES.md](docs/RULES.md) (proof, git, secrets,
  long jobs, production, documents), [pipeline/README.md](pipeline/README.md) (the files between agents).

## Repository map

| Path | Role |
|---|---|
| `CLAUDE.md`, `docs/RULES.md` | the kernel, loaded at every call (kept short on purpose) |
| `supervisor/` | the supervisor's role, onboarding, handoff, log watcher |
| `bin/harness/` | orchestrator, duo loop, reviewer, coder, gate, blind judge, mediator, prompts, offline tests |
| `bin/doctor.ps1` | checks prerequisites and configuration |
| `bin/benches/` | bench conventions, harness lint |
| `pipeline/` | the thread between reviewer and coder (task, report, verdict, owner's box) |
| `docs/` | vision, rules, roadmap, plan, backlog, ADRs, state, questions, owner page, taste, art direction |
| `.claude/skills/` | thin domain skills (stack, proofs, art-judge, ui-ux, game-feel, systems-design, determinism, networking, load-test, build-release, pipeline-3d, pipeline-audio) |
| `tools/` | lanes, ADR index, costs dashboards, image thumbnails and boards, captures, optional asset pipelines |
| `config/` | `project.env` (models, gate commands, options), `duos.txt` |

## What it costs

Each task costs one reviewer pass and one coder session; a duo with nothing to do costs nothing. Expect a
few dollars per task (API-equivalent) with the default model table; the onboarding asks your plan and
budget and sets the table accordingly. Measure it any time: `python tools/costs/agg_logs.py`,
`python tools/costs/loop.py`.

## Status

The process ran for ~650 tasks on the project it was extracted from. This generic version renames and
de-projectifies it; the harness is covered by offline tests with a fake Claude
(`bin/harness/test/`). Report what breaks for you in an issue; lessons from your project are welcome
(`docs/UPSTREAM.md` format).
